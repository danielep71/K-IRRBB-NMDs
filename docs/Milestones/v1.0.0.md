# 🚀 v1.0.0 — First validated NMD application

[← Index](README.md) · [GitHub milestone](https://github.com/danielep71/K-IRRBB-NMDs/milestone/10) · [Previous: v0.9.0](v0.9.0.md)

## 🎯 Objective

Release the first stable Excel/VBA application for the agreed
non-maturity-deposit behavioral-modeling scope: validated data import,
Rates/Stable/Decay calibration, diagnostics, historical backtesting, coherent
scenarios, applicable regulatory overlays and controlled ALM parameter and
profile export.

**Why it matters.** A stable version number is a commitment to the content
actually delivered. Users must be able to identify which workbook to use,
which source produced it, which environment was tested and which operations
are supported. Final acceptance prevents an internal candidate or development
folder from being mistaken for an accepted product.

## 📦 Scope

- Obtain owner acceptance of the qualified [v0.9.0](v0.9.0.md) candidate,
  confirming its scope and remaining limitations.
- Document model, API and export versions and their limitations, with
  instructions for any supported incompatibility handling or migration.
- Build, test and hash the workbook against the release source.
- Publish final release notes, installation guide and synthetic examples
  consistent with the final source and the behavior actually tested.
- Tag, release and distribute only under the recorded release approval,
  following [`RELEASING.md`](../../RELEASING.md).

The delivered product covers controlled data import with segmentation,
reconciliation and lineage; verified Decay profiles with explicit
assumptions; Rates calibration and customer-rate simulation; Stable survival
with consistent aggregation; versioned parameters and reproducible
backtesting; scenarios and verified overlays kept separate from the fit; the
workbook workflow, save/load and a controlled ALM schema; and installation,
examples, methodology, versions and limitations.

## 🏁 Exit criteria

- [ ] Owner acceptance and authorization for the intended publication or
  distribution are recorded.
- [ ] The final commit passes static checks, Excel compile, Excel tests,
  numerical references and scenarios, with explicit limitations.
- [ ] Workbook and source correspond; build, test results and hashes are
  documented.
- [ ] Release notes, installation instructions, examples and contract
  versions accurately describe the delivered product.
- [ ] Authorized tags, releases and artifacts follow `RELEASING.md`, and
  post-publication checks pass; a published artifact is never silently
  replaced and a tag is never moved.

**Example acceptance case.** A user follows the installation guide, opens the
distributed workbook and reproduces a complete synthetic example; results
match the published evidence within the stated tolerances. Source identity,
model version, configuration and artifact hash identify the exact product
used and support reproducible defect reports.

## 🔗 Tracked issues and dependency

No dedicated issues yet: track acceptance, distribution and final

## 🚫 Not in scope

Full banking-book EVE/NII calculation unless separately approved, and any
external numerical runtime in the workbook; offline tools that produce
independent reference values stay distinct from runtime dependencies.
"Validated" means the checks defined for this project, scope, source and
documented environments; it is not regulatory approval and does not replace
a bank's own internal validation. This milestone does not by itself
authorize publication, distribution or a visibility change.
