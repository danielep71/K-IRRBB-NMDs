# 📉 v0.3.0 — Decay model

[← Index](README.md) · [GitHub milestone](https://github.com/danielep71/K-IRRBB_Behavioral_Models/milestone/3) · [Previous](v0.2.0.md) · [Next →](v0.4.0.md)

## 🎯 Objective

Deliver an independently tested Decay engine in the Excel application:
aggregate balance dynamics per segment and currency, producing
minimum-probable-amount profiles, runoff and mean life under the accepted
contract.

**Why it matters.** Translating balances without contractual maturity into a
time profile requires explicit assumptions, observed variability, a horizon
and a runoff allocation. A declining chart alone does not establish
correctness: amounts must reconcile to the opening balance, and statistics
must be compared with values produced independently of the VBA
implementation.

## 📦 Scope

- Review and consolidate the draft decay model merged into `release/v0.3.0`
  from `test/36-decay-review` (#94) and integrated into `main` (#97): its
  source, generators, examples and expected values. Reuse only work that meets
  architecture, contract and verification requirements; being merged does not
  make the prototype an accepted deliverable.
- Prepare the series: aggregate balances by segment and currency, log-balance
  changes and declared structural breaks, with domain, continuity and
  sample-size rules.
- Estimate drift, break effects and residual volatility, recording settings
  and contract-required diagnostics with distributional assumptions explicit.
- Build the profile: minimum probable amounts, runoff, terminal remainder,
  core and non-core measures and mean life, explaining the conservative growth
  treatment and terminal-remainder allocation.
- Document the aggregate-balance reading (the series includes new accounts),
  the growth treatment and the absence of a direct rate-scenario input.
- Settle the open decisions in #36: censored disappearances (`W05`) in the
  aggregate series, break-date convention, median path, diagnostic settings
  and backtest horizons 1 to 12.
- Keep statistical outputs separate from regulatory constraints; the
  prototype's overlay code stays distinct.
- Add independent numerical cases and a repeatable worked example to the
  v0.2.0 harness, and the `DecayExample` sheet the example reads.

## 🏁 Exit criteria

- [ ] Coefficients, volatility, profiles and mean lives match independent
  references within justified, recorded tolerances.
- [ ] Tests cover notional conservation, monotonicity, structural breaks,
  domain boundaries, insufficient samples and failure paths.
- [ ] Generators and expected values have provenance, versions and seeds; no
  expected value is copied from the output under test.
- [ ] Invalid input (short samples, non-month-end dates, gaps, non-positive
  balances, unknown segments, currencies outside the allowlist) is rejected
  with controlled errors.
- [ ] Compilation, regressions and the worked example run on Windows 64-bit
  Excel on the exact commit, with failures and cleanup documented.
- [ ] Existing data-import results are unchanged.
- [ ] README, CHANGELOG, `MODEL_CONTRACTS.md`, `TEST_CASES.md` and this guide
  state what is implemented, tested, independently validated and excluded.

**Example acceptance case.** For a synthetic monthly series, the user selects
the window, segment, currency and supported settings. The output contains
coefficients, diagnostics and a profile whose amounts can be reconstructed;
runoff plus the terminal remainder equals the opening balance within the
stated tolerance, and the profile satisfies the contract's properties in
boundary cases as well as ordinary ones. Because the aggregate series includes
new accounts, its dynamics do not automatically represent survival of
balances present at the origin; the results state this distinction, which is
central to later composition with Stable.
