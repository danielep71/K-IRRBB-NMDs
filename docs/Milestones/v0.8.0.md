# 🖥️ v0.8.0 — User workflow and ALM export

[← Index](README.md) · [GitHub milestone](https://github.com/danielep71/K-IRRBB_Behavioral_Models/milestone/8) · [Previous](v0.7.0.md) · [Next →](v0.9.0.md)

## 🎯 Objective

Make the validated model workflow usable without editing VBA, and its outputs
safely transferable through a generic, versioned ALM parameter and profile
export.

**Why it matters.** A correct engine is not enough if users cannot
distinguish current results from previous ones, load incompatible parameters
or export profiles with ambiguous units. This phase makes state,
configuration, limitations and provenance visible while preserving earlier
controls through saving, reopening and exporting.

## 📦 Scope

- Provide a guided workbook workflow with commands and checks for loading,
  calibration, backtesting, scenarios and export.
- Expose supported segments, currencies, windows and options, so the settings
  actually used are always identifiable.
- Show diagnostics: summaries, errors, exclusions and model limitations.
- Save and load versioned parameter sets with compatibility checks.
- Produce readable calibration, test and scenario reports connected to their
  evidence.
- Define a generic ALM export with versioned schema, fields, units, segment
  and currency identifiers, horizons, run identity and provenance; the
  concrete format is specified and reviewed in its implementation issue.
- Write user documentation and worked synthetic examples.

## 🏁 Exit criteria

- [ ] A user completes load, calibrate, backtest, scenario and export on a
  synthetic example without editing VBA, following documented instructions.
- [ ] Results, settings, model versions and provenance are consistent across
  the workbook, saved parameters and exports.
- [ ] Exports reconcile to displayed amounts without implicit unit conversion
  or aggregation.
- [ ] Incompatible parameter versions are rejected; stale, failed or
  incomplete runs cannot produce valid-looking exports.
- [ ] Model results from v0.3.0–v0.7.0 are unchanged.
- [ ] Save and reopen, cancellation, failure handling and cleanup run on
  Windows 64-bit Excel on the exact commit, alongside the ordinary workflow.
- [ ] README, INSTALLATION, CHANGELOG, the user documentation and this guide
  describe the workflow, export schema and limitations.

**Example acceptance case.** A user completes a synthetic case, saves the
calibration, and closes and reopens the workbook. Loading checks the
parameter version and displays its essential information, and an exported
profile reconciles to the displayed results. After the user changes data or a
relevant setting, previous results become outdated and cannot be exported as
valid results for the new configuration.

## 🚫 Not in scope

Vendor-specific ALM adapters, which need an explicit integration contract and
verification with the receiving system; an export file is not proof of
acceptance by an ALM system. No external numerical engine in the workbook.

## 🧪 Release evidence

- Pass `python tools/check.py --ci` and the hosted Repository integrity check
  on the exact candidate.
- Record Windows Excel 64-bit stages 1–6 of
  [`EXCEL_EVIDENCE.md`](../EXCEL_EVIDENCE.md), the full user workflow, save
  and reopen, cancellation, failure and cleanup runs.
- Record export reconciliation against displayed results and the schema
  version used.
- Record the candidate SHA, the source round trip, limitations and
  documentation updates.
- Do not tag, publish or merge to `main` without explicit owner authorization.
