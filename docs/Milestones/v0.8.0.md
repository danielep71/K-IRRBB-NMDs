# 🖥️ v0.8.0 — User workflow and ALM export

[← Index](README.md) · [GitHub milestone](https://github.com/danielep71/VBA-IRRBB-Toolkit/milestone/8) · [Previous](v0.7.0.md) · [Next →](v0.9.0.md)

## 🎯 Purpose

Make the model workflow usable from the workbook and transfer results
to ALM applications in a controlled way. Users must be able to load data,
calibrate, run backtests and scenarios, and export results without editing
VBA source.

## 💡 Why it matters

A correct engine is not enough if users cannot distinguish current results
from previous ones, load incompatible parameters, or export profiles with
ambiguous units. This phase makes state, configuration, limitations, and
provenance visible while preserving earlier controls through saving,
reopening, and exporting.

## 🛠️ Activities and deliverables

| Area | Planned capability | User outcome |
| --- | --- | --- |
| Guided workflow | Commands and checks for loading, calibration, validation, simulation, and export | Understandable sequence without editing VBA |
| Configuration | Expose supported segments, currencies, windows, and options | Settings actually used are always identifiable |
| Diagnostics | Summaries, errors, exclusions, and model limitations | Users can understand missing or rejected results |
| Persistence | Save and load versioned parameter sets | Controlled reuse with compatibility checks |
| Reports | Readable calibration, test, and scenario results | Results remain connected to their evidence |
| ALM export | Generic versioned schema for parameters and profiles | Interpretable output with units, identifiers, and provenance |

The export schema must define fields, units, segments, currencies, horizons,
versions, and run identity. Specify and review its concrete format in the
implementation issue; this guide does not impose an unapproved file layout.

## 🔎 Practical example

A user completes a synthetic case, saves the calibration, and closes and
reopens the workbook. Loading checks the parameter version and displays
its essential information. An exported profile reconciles to the displayed
results. If the user changes data or a relevant setting, previous results
become outdated and cannot be exported as valid results for the new
configuration.

## 🔗 Dependencies

The [v0.6.0](v0.6.0.md) orchestration and parameter versioning,
[v0.7.0](v0.7.0.md) scenarios and constraints, and v0.2.0 workbook are required.
This phase completes user interaction; it does not defer essential failure
handling or stale-result controls already required in earlier phases.

## ✅ Completion criteria

- Users can complete data loading, calibration, backtesting, scenarios,
  and export without editing VBA, using documented instructions and a
  reproducible synthetic example.
- Results, settings, model versions, and provenance are readable and
  consistent across the workbook, saved parameters, and exports.
- Incompatible parameter sets are rejected. Failed, incomplete, or outdated
  runs cannot produce exports that appear valid.
- Exports reconcile to displayed amounts without implicit unit conversions
  or aggregation.
- Saving, reopening, cancellation, failure handling, and cleanup run in
  Excel on the exact commit, alongside the ordinary workflow.

## 🚧 Boundaries and tracking

The export is generic. A vendor-specific adapter requires an explicit
integration contract and verification with the receiving system; producing
an export file does not prove that an ALM system accepted it. The workbook
does not require an external numerical engine for its calculations.

As of October 9, 2026, no dedicated issues are assigned to this milestone.
Before development, break down user workflow, persistence, reporting, and
export into verifiable activities, each assigned to `danielep71` with a
milestone and exactly one priority. This guide describes the planned scope;
it does not claim that those activities already exist or are complete.
