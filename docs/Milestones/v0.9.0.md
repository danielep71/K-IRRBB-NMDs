# 🧪 v0.9.0 — Release candidate

[← Index](README.md) · [GitHub milestone](https://github.com/danielep71/VBA-IRRBB-Toolkit/milestone/9) · [Previous](v0.8.0.md) · [Next →](v1.0.0.md)

## 🎯 Purpose

Qualify the complete agreed NMD application on a candidate identified by
one exact commit. Consolidate evidence collected during development and
verify that source, workbook, documentation, installation, and failure
recovery work together before the stable release.

## 💡 Why it matters

Individually tested components do not guarantee an installable, reproducible
final package. Differences in the built workbook, host configuration, or
instructions may prevent users from obtaining the validated outcome.
The release candidate ties all evidence to the same source and the actual
artifacts produced from it.

## 🛠️ Activities and deliverables

1. **Freeze scope and candidate.** Identify features, commit, environments
   to test, and acceptance criteria. New features require scope and evidence
   to be reassessed.
2. **Consolidate validation.** Collect independent references, tolerances,
   regressions, and model evidence, then run the complete workflow on the
   candidate. Validation begins in the model milestones; it is not deferred
   to this phase.
3. **Verify operational use.** Exercise installation, upgrade, rollback,
   and recovery with agreed data volumes and performance targets. Record
   environment and workload; do not introduce undecided thresholds or
   generalize from a single case.
4. **Align documentation.** Check instructions, examples, methodology,
   supported versions, and limitations against the features actually tested.
5. **Review provenance and distribution.** Review the candidate and relevant
   history under governance, recording licensing, rights, and material
   review before the intended distribution.
6. **Build and identify artifacts.** Retain the build procedure, source
   identity, test results, and candidate workbook hash.

## 🔎 Practical example

A clean candidate checkout must allow the workbook to be built and opened,
synthetic data to be loaded, models to be calibrated, tests and scenarios
to be reproduced, and reconciled results to be exported. The evidence
package records the commit, Excel host, configuration, assertions,
tolerances, and outcomes. An intentional failure verifies recovery in
the actual package intended for users.

## 🔗 Dependencies

Deliverables from v0.2.0–v0.8.0 and their resolved prerequisites are required.
Supported-environment claims must match the evidence; unverified environments
remain explicit. The [release procedure](../../RELEASING.md) governs the
frozen source, artifacts, and subsequent steps.

## ✅ Completion criteria

- All required tests pass on the exact candidate, no blocking defect
  remains, and accepted limitations are documented.
- Independent values, tolerances, Excel tests, and end-to-end execution
  evidence are tied to identified source and artifacts.
- Installation, upgrade, rollback, failure recovery, and agreed performance
  checks have recorded, reproducible results.
- The workbook is built from the intended source, tested, and identified
  by its hash; instructions allow the procedure to be repeated.
- The distribution review is recorded for the intended candidate.
- If source changes after certification, update the evidence and rerun
  the required checks under RELEASING.md.

## 🚧 Boundaries and tracking

Closing this milestone does not automatically publish a tag, release, or
workbook, or change repository visibility. Final acceptance belongs to
v1.0.0 and requires the specified authorizations.

As of October 9, 2026, no dedicated issues are assigned. Before qualification,
create activities for candidate freeze, the test matrix, packaging,
documentation, and distribution review, each with an assignee, milestone,
priority, and acceptance criteria.
