# 📊 v0.2.0 — Workbook, data and Excel tests

[← Index](README.md) · [GitHub milestone](https://github.com/danielep71/K-IRRBB-NMDs/milestone/2) · [Previous](v0.1.0.md) · [Next →](v0.3.0.md)

## 🎯 Objective

Deliver the first reproducible Excel application shell and a reliable data
pipeline: a workbook rebuilt from reviewed source, contract-conformant data
loading, and a test harness that runs inside Excel.

**Why it matters.** Later models depend on correct data, reproducible imports,
and results whose validity and freshness are clear. An error in balance
loading or information-availability dates can distort an estimate even when
the formula is correct, and a manually assembled workbook makes it difficult
to identify the code that actually ran. This milestone controls those risks
at their source.

## 📦 Scope

- Create the sanitized, macro-free `.xlsx` template: sheet names, CodeNames,
  input and output areas and ownership, with reserved areas clearly marked;
  a worksheet name is not evidence that a feature exists (#5).
- Define ordered VBA component import and export with encoding, line endings,
  resources and recovery; Excel settings are restored on failure, and a
  cleanup failure accompanies rather than conceals the original failure (#6).
- Build the Excel harness: case identifiers, assertion counts, PASS / FAIL /
  NOT RUN outcomes and a first smoke test on the agreed host (#8).
- Import the account and market-data CSV files per
  [`DATA_CONTRACT.md`](../methodology/DATA_CONTRACT.md): validation,
  segmentation, reconciliation and lineage, all-or-nothing, with stale
  results invalidated (#71).
- Apply the point-in-time rules: observation versus availability dates;
  closure, missing extract, gap and right censoring; leakage tests (#32,
  before affected transformations).
- Diagnose issue-metadata failures on PR events and log safe API errors (#41).

## 🏁 Exit criteria

- [ ] A clean checkout builds the workbook from source, and the import/export
  round trip is verified.
- [ ] Valid synthetic data yields the expected summaries and reconciliations.
- [ ] Invalid input is rejected with controlled errors, no partial outputs and
  no stale results shown as current.
- [ ] Timing, closure and missing-data cases follow the accepted #32
  amendment.
- [ ] The harness compiles and runs on Windows 64-bit Excel, including
  repeated runs and failure recovery, with evidence tied to the exact commit
  ([`EXCEL_EVIDENCE.md`](../EXCEL_EVIDENCE.md)).
- [ ] Unexecuted cases and environment limitations are explicit; LibreOffice
  and static CI are not presented as Excel evidence.
- [ ] README, INSTALLATION, CHANGELOG and this guide state what is
  implemented, tested and still excluded.

**Example acceptance case.** A forecast made on March 31 cannot use a May
closure learned in June. If an account disappears from the April extract, the
system distinguishes a closure from missing data. A test changes information
learned after March and checks that predictors available in March remain
identical. Another test loads an invalid CSV after a successful import and
verifies that previous results no longer appear current.

## 🚫 Not in scope

Estimating or certifying any econometric model. The draft decay model on the
branch, merged for v0.3.0 (#94) and present here since the branch was
levelled with `main`, belongs to v0.3.0 (#36) and does not itself prove
import/export behavior or Excel execution; the rate and stable-amount models
are not built.

## 🧪 Release evidence

- Pass `python tools/check.py --ci` and the hosted Repository integrity check
  on the exact candidate.
- Record Windows Excel 64-bit stages 1–6 of
  [`EXCEL_EVIDENCE.md`](../EXCEL_EVIDENCE.md): clean build, compile, smoke
  run, failure path (injected failures and write fault), cleanup and
  application-state restoration, and the source round trip.
- Record independent expected values for every implemented calculation, with
  derivation and tolerances.
- Record the candidate SHA, limitations and documentation updates, and close
  the licensing and distribution review.
- Do not tag, publish or merge to `main` without explicit owner authorization.
